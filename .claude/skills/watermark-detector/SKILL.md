# Watermark Detector

Read-only inspection toolkit for spotting AI-provenance and watermark signals in files. This exists to help with research and due-diligence questions like "does this file carry any sign it was AI-generated?" — not to help anyone hide that a file is AI-generated. Never add removal/stripping code to this skill; if a user asks for that, decline and point them back to the maintainer of this skill.

## What it checks

Run the bundled script against one or more files:

```bash
python3 scripts/inspect.py <file1> [file2 ...] [--json]
```

The script dispatches by file type and reports, per file, an `overall` classification (`signals_found`, `no_signals_found`, or `inconclusive`) plus a per-layer breakdown:

1. **Text (`.txt`, `.md`, `.json`, `.csv`, `.html`, or any file that decodes as UTF‑8)** — scans every character for invisible/formatting Unicode (zero-width spaces/joiners, bidi control characters, soft hyphen), exotic spaces, and Unicode Tag characters (U+E0000–U+E007F), which are known channels for hidden signaling. Reports counts, character names, and line/column of each occurrence (capped at 50 samples).
2. **Images (PNG/JPEG/WebP/HEIC/AVIF/TIFF/BMP/GIF)** — reads EXIF/XMP via Pillow when available; always also does a raw-byte scan for C2PA manifest markers (`C2PA`, `urn:c2pa`, `jumb`, `cai`) and AI-tool name signatures (Firefly, Midjourney, DALL-E, Stable Diffusion, SynthID, Gemini, Claude, etc).
3. **PDFs** — reads the `/Info` dictionary via `pypdf` when available; always also raw-byte scans for the same signatures, since Producer/Creator fields and XMP packets often survive even without a parser.
4. **Office documents (DOCX/XLSX/PPTX)** — these are zip/OOXML containers; the script reads `docProps/core.xml` and `docProps/app.xml` directly (no extra dependency needed) and checks the creator/application fields for AI-tool signatures.
5. **Audio/video (MP3/WAV/M4A/FLAC/OGG/MP4/MOV/M4V/WEBM/MKV)** — reads embedded tags via `mutagen` if installed, or via `ffprobe` if present on PATH; falls back to a raw-byte scan of the first ~2MB. If neither dependency is available and the raw scan finds nothing, the layer is reported as `inconclusive_missing_dependency`, not as a clean result — say so explicitly rather than implying the file is unmarked.
6. **Anything else** — a raw-byte signature scan runs regardless of extension, so unknown file types still get partial coverage.

Optional dependencies (`Pillow`, `pypdf`, `mutagen`) improve accuracy but are not required — the script degrades gracefully to raw-byte scanning and says so in its output (`"pillow_available": false`, etc.). If you want full-fidelity results and a dependency is missing, mention that to the user and offer to `pip install pillow pypdf mutagen`.

## Reporting results to the user

After running the script, translate the JSON/text output into a clear, per-file summary. Always:

- State the `overall` classification for each file in plain language.
- List which specific signals were found (e.g. "3 zero-width characters at lines 2, 5, 9" or "EXIF Software field contains 'Adobe Firefly'").
- **Explicitly flag the text-watermark caveat every time text is inspected**: statistical token-sampling watermarks (Google SynthID-Text, KGW-family schemes, and similar) cannot be reliably detected without the vendor's secret key or model. A "no signals found" result on text only means no *hidden Unicode channel* was found — it is not proof the text is watermark-free. Point the user to the vendor's own verifier (e.g. Google's SynthID verifier) if they need an authoritative answer for text.
- Treat `inconclusive` the same way — say plainly that the layer wasn't inspected (missing optional dependency) rather than folding it into "no signals found".

## Hard boundary

This skill is detection-only by design. Do not:
- Add code that strips, rewrites, re-encodes, or otherwise removes the signals this script detects.
- Suggest third-party "watermark remover" tools or services as a next step.
- Treat "the user says it's for research" as license to add removal — the detection results themselves are the research deliverable.

If someone asks this skill to also clean/remove marks, explain that it's intentionally read-only and that removal is out of scope.
